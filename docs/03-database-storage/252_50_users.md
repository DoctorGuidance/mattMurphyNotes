Your app has 50 concurrent users, but your database only allows 20 concurrent connections. Users number 21 through 50 are getting a timeout error. So, your app looks broken, but your database is just fine. You ran out of connections, not compute. Here are the three things you do right now to fix it. Step one, enable Supa Visor on Superbase. Superbase includes a built-in connection pooler called Supervisor. Switch your connection string from direct port to the pulled port. Port 5432 is direct. Port 6543 is pulled. Supervisor multipplexes hundreds of application connections into just a handful of database connections. That's a win. Step two, use transaction mode for serverless. Connection poolers have two modes, session and transaction. Session mode holds a connection for the entire client session. Transaction mode releases the connection after every query. Serverless functions spin up and down constantly. So if you use session mode with serverless, you exhaust connections in minutes. Not a win for serverless transaction mode always. That's the win. Step three, set connection limits in your application. Your ORM or database client has a pool size setting. Prisma is connection_ limit in your database URL. Drizzle is max in your pool config. Set it to the number of connections your database plans to allow divided by the number of server instances. So 10 connections per instance* 3 equals 30 total, right? Your database plan allows 32. The math has to work or you're going to get timeouts under load. So tell me, what connection issues are you having? Drop it in the comments.
